## 改了什么

今天给博客做了两个界面层面的升级：

1. **首页新增侧边个人信息栏**：头像、简介、社交链接、文章/分类/标签统计、快捷导航
2. **导航结构统一 + 图标化**：所有导航项配上 SVG 图标，侧边栏去掉了与顶栏重复的入口

## 为什么改

### 原来有什么问题

博客上线后，首页就是一串文章列表——没有个人信息、没有导航引导，读者进来只能看到标题和摘要。作为博客，少了点"人味"。

导航也有明显的重复：

- 顶栏：「首页」「文章▼（分类/标签/归档）」「关于」
- 侧边栏：「首页」「分类」「标签」「归档」「关于」「友链」

分类、标签、归档这三个入口同时在顶栏下拉和侧边栏出现，既不简洁，也让读者困惑——同一个链接到底从哪进？

### 目标

- 首页有个人品牌展示区，读者一眼知道这是谁的博客
- 导航不重复，每个入口只出现一次
- 所有导航项配上一致的图标，看起来整齐专业

## 怎么做的

### 侧边栏

侧边栏是一个独立的 Astro 组件，放在首页的两栏布局左侧（移动端自动叠放）。它分四个区域：

```
┌─────────────┐
│  [头像]      │  ← 个人信息区
│  AirevaDo    │
│  个人博客...  │
├─────────────┤
│ 4     2    3 │  ← 统计区
│ 篇文章 分类 标签│
├─────────────┤
│ [GitHub]    │  ← 社交链接区
├─────────────┤
│ 📄 首页     │  ← 导航区（仅保留
│ 👤 关于     │     顶栏没有的入口）
│ 🔗 友链     │
└─────────────┘
```

组件接收 `postCount`、`categoryCount`、`tagCount` 三个参数，统计数据从内容层查询后传入——组件自己不查数据，保持纯粹。

社交链接用了可配置的设计：在 `site.config.ts` 里定义数组，Sidebar 循环渲染。以后要加 B 站、知乎之类的链接，改配置就行，不用动组件代码。

### 导航图标统一

这是最花心思的细节。改了三个地方：

**顶栏顶层导航**——「首页」加了房子图标，「关于」加了用户图标，「文章」加了书本图标。风格统一用 Feather Icons 的线条风：`16×16`、`stroke="currentColor"`，颜色自动跟随文字，深色模式下不用额外处理。

**顶栏下拉菜单**——「分类」（文件夹图标）、「标签」（标签图标）、「归档」（盒子图标）。这部分之前就有图标，这次保持不变。

**侧边栏导航**——去掉了「分类」「标签」「归档」（它们已经在下拉菜单里了），只保留「首页」「关于」「友链」，每项前面换成图标，替代了之前简陋的 `—` 短线。

最终效果：所有导航项不论在哪个位置，图标风格完全一致，视觉上是一个整体。

### 技术细节

图标用了内联 SVG，通过 Astro 的 `Fragment set:html` 渲染：

```astro
{ label: "首页", href: `${base}/`, icon: `<svg ...>...</svg>` }
```

```html
<a href={item.href}>
  <Fragment set:html={item.icon} />
  {item.label}
</a>
```

为什么不用 icon font 或者 `<img>`？内联 SVG 的好处是：
- 颜色通过 `stroke="currentColor"` 继承文字颜色，深色模式自动适配
- 零额外 HTTP 请求
- 可以用 Tailwind 的 `h-4 w-4` 控制尺寸

## 踩坑

这次有个小遗漏：CR-005 给「首页」和「关于」加了图标后，忘了「文章」按钮。「文章」是下拉菜单的触发器，渲染逻辑不在 `topLevelItems` 循环里，被漏掉了。发现后补了个书本图标上去——现在三个顶层导航项视觉统一了。

这也说明：**能复用数据结构的，就尽量让它驱动所有渲染**。如果「文章」按钮也从同一个数据数组里取图标，就不会漏。

## 总结

两个改动加起来不到 80 行代码，但从视觉和使用体验上提升不少。博客不再是一串冷冰冰的标题列表，有了点"个人空间"的感觉。
