# 产品概述

## 1. 项目愿景 (Vision)
> 为自己打造一座**数字花园**——系统化沉淀知识、串联思考，同时对外输出技术文章与随笔，逐步建立个人知识品牌。

## 2. 核心价值 (Value Proposition)
*   **用户价值**：以 Markdown + Git 工作流为核心，实现「写完即发布」的零摩擦知识管理体验；全文搜索让历史积累随时可检索，避免知识沉没。
*   **商业/技术价值**：纯静态架构，零服务器成本运行；第三方评论（Giscus）降低运维负担；Git 驱动的发布流程天然适配开发者。

## 3. 核心板块 (Core Modules)

### 3.1 内容创作与管理
*   **描述**：Markdown 文件即文章，通过 Git 提交触发构建与发布。支持分类、标签、归档三种组织维度。
*   **关键特性**：
    *   Markdown 编写，支持代码高亮、数学公式
    *   分类（category）+ 标签（tag）双维度组织
    *   按时间自动归档
    *   图片/资源本地化管理

### 3.2 阅读与发现
*   **描述**：为读者（包括自己）提供流畅的浏览、搜索与交互体验。
*   **关键特性**：
    *   全文搜索，快速定位历史内容
    *   深色模式（浅色 / 深色切换）
    *   响应式布局，适配手机、平板、桌面
    *   关于页、友链页、归档页

### 3.3 分发与互动
*   **描述**：让文章可被发现、可被讨论。
*   **关键特性**：
    *   SEO 基础（sitemap、meta 标签、静态生成）
    *   Giscus 第三方评论系统（基于 GitHub Discussions）
    *   文章链接永久化，不随重构变更

## 4. 目标用户 & 核心场景 (User & Scenes)
### 4.1 目标用户
*   **自己（核心）**：后端/全栈开发者，需要系统化整理技术笔记、踩坑记录、读书感想，要求检索快、写作零摩擦。
*   **技术同行（次要）**：后端/全栈方向的开发者，通过搜索或友链进入，期望获得有深度的技术总结。
*   **普通读者（偶发）**：通过生活随笔、读书感想了解作者，不要求技术背景。

### 4.2 核心场景 (Key Use Cases)
*   **场景 1**：自己在本地写完一篇技术笔记，`git push` 后自动部署上线，无需额外操作。
*   **场景 2**：自己或读者在博客中通过关键词搜索，快速找到相关历史文章。
*   **场景 3**：技术同行通过搜索引擎（如 Google "Go 并发模式"）进入某篇文章，阅读后在底部 Giscus 评论区提问。

## 5. 关键业务流程 (Core Workflows)
> 作者本地编辑 Markdown → Git 提交推送 → 触发静态站点构建（CI/CD）→ 生成 HTML 页面 → 部署至静态托管平台 → 读者通过浏览器访问（含搜索、评论）

## 6. 验收标准 (Acceptance Criteria)
*   **功能完备性**：
    *   能写（Markdown 写作，分类/标签/归档正常运作）
    *   能搜（全文搜索可用，中文分词准确）
    *   能看（响应式布局，手机/平板/桌面均可正常阅读）
    *   能互动（Giscus 评论正常加载）
*   **技术指标**：
    *   首页加载 < 2s（Lighthouse Performance > 90）
    *   构建时间 < 2min
    *   零运行时成本（仅使用免费平台）

## 7. 约束条件 (Constraints)
*   部署成本：零成本优先（使用免费静态托管平台 + 免费二级域名）
*   开发周期：2–4 周上线第一个可用版本
*   内容管理：纯 Markdown + Git，无后台管理界面
*   认证体系：无登录/注册功能
*   语言：仅中文

## 8. 项目边界 (Out of Scope)
*   不提供后台管理界面（CMS）
*   不实现用户注册/登录系统
*   不做多语言（i18n）
*   暂不做 RSS 订阅
*   暂不做访问统计（如 Google Analytics）
*   暂不做社交分享按钮
*   暂不做邮件订阅/Newsletter
