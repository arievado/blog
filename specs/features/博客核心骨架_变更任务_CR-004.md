### Task-12：Sidebar 个人信息栏组件

**通俗解释**：做一个独立的"个人信息卡片"组件，包含头像、名字、简介、社交图标、文章/分类/标签统计数、导航链接。首页和以后其他页面都可以复用。

**做什么**：

1. **新建 `src/components/Sidebar.astro`**：
   - Props 接收 `postCount`、`categoryCount`、`tagCount`（三个 number）
   - 从 `constants.ts` 读取 `SITE_AVATAR`、`SITE_AUTHOR`、`SITE_BIO`、`SITE_SOCIAL_LINKS`

2. **个人资料区**：
   - 头像 `<img>`：`h-24 w-24 rounded-full object-cover`，含 `onerror` 占位处理（复用 Header 的头像占位逻辑）
   - 昵称 `<h2>`：`SITE_AUTHOR`，字号 `text-xl font-bold`
   - 简介 `<p>`：`SITE_BIO`，`text-sm text-gray-500 dark:text-gray-400`

3. **社交图标区**：
   - 遍历 `SITE_SOCIAL_LINKS`，每个渲染为 `<a>` 外链，`target="_blank" rel="noopener noreferrer"`
   - 内联 SVG 图标映射表（icon → SVG path），至少支持 `github`、`email`、`rss`
   - 图标 20x20，hover 时变色（`text-gray-500 hover:text-accent` 或类似）
   - 横排排列，`gap-3`

4. **统计区**：
   - 三组数字：文章数、分类数、标签数
   - 每组：数字加粗 + 单位小字（如「**5** 篇文章」「**3** 个分类」「**8** 个标签」）
   - 布局灵活：横排或竖排均可，保持视觉清晰

5. **导航菜单区**：
   - 链接列表：`首页(/)、归档(/archive/)、分类(/blog/category/)、标签(/blog/tag/)、关于(/about/)、友链(/friends/)`
   - 内联 `<nav>` 标签，每个链接为块级 `<a>`
   - 装饰：每项前加短线 `—` 或小圆点 `·`
   - hover 时文字变主题色，轻微左移（`hover:translate-x-1 transition-transform`）

6. **深色模式适配**：所有颜色使用 `dark:` 变体

**涉及文件**：`src/components/Sidebar.astro`（新建）

**参考**：技术方案 5.6 → AC-038, AC-039, AC-040

**依赖**：Task-11（`SITE_SOCIAL_LINKS` 可用）

**预估工时**：50 分钟

**验证标准**（TDD RED 阶段依据）：

- [x] Sidebar 组件文件存在且可被 import
  - **Given** Sidebar.astro 已创建，**When** 在 index.astro 中 `import Sidebar from "../components/Sidebar.astro"`，**Then** 构建不报错
- [x] 头像和作者信息区域渲染正确
  - **Given** site.config.ts 配置了头像、作者、简介，**When** 构建并访问首页，**Then** Sidebar 内可见头像 `<img>`、作者名 `<h2>`、简介 `<p>`
- [x] 社交图标链接渲染正确
  - **Given** site.config.ts 配置了 GitHub 链接，**When** 查看 Sidebar 渲染结果，**Then** 包含指向 `github.com` 的 `<a>` 标签，且含 `target="_blank"`
- [x] 统计数据渲染正确
  - **Given** `postCount=2, categoryCount=1, tagCount=3`，**When** Sidebar 渲染，**Then** 可见 "2" 和 "篇文章"、"1" 和 "个分类"、"3" 和 "个标签"
- [x] 导航链接包含至少 4 个目标页面
  - **Given** Sidebar 组件，**When** 检查渲染的 `<nav>` 区域，**Then** 至少包含指向 `/`、`/archive/`、`/blog/category/`、`/about/` 的链接
- [x] 深色模式下 Sidebar 颜色与全局一致
  - **Given** 站点切换为深色模式，**When** 查看 Sidebar，**Then** 文字、背景、链接颜色与 `dark:` 变体定义一致，无突兀亮色

### Task-13：首页两栏布局重构

**通俗解释**：把首页从"上面头像简介 + 下面文章列表"改成"左边个人信息栏 + 右边文章列表"的经典布局，手机上看则自动上下堆叠。

**做什么**：

1. **修改 `src/pages/index.astro`**：
   - 移除现有 Hero 区域（头像 `<img>` + 简介 `<p>` + 内联 `<script is:inline>` 的 onerror 处理）
   - 额外获取统计数据：`const categories = await getAllCategories(); const tags = await getAllTags();`
   - 导入 Sidebar 组件：`import Sidebar from "../components/Sidebar.astro"`
   - 将 `<BaseLayout>` 内的 slot 替换为两栏布局：

   ```
   <BaseLayout>
     <div class="flex flex-col gap-8 lg:flex-row">
       <Sidebar postCount={...} categoryCount={...} tagCount={...} />
       <main class="flex-1 min-w-0">
         <PostList posts={posts} />
       </main>
     </div>
   </BaseLayout>
   ```

2. **布局细节**：
   - Sidebar 列：`w-full lg:w-72 shrink-0`（桌面端固定 288px 宽）
   - 文章列表列：`flex-1 min-w-0`（防止内容溢出）
   - 间距：`gap-8`（两栏之间 + 移动端堆叠间距）

3. **清理**：移除 `index.astro` 中不再需要的 import（`SITE_AVATAR`、`SITE_BIO`，如果仅 Hero 使用）、移除 Hero 区 onerror 脚本（Sidebar 内已有）

**涉及文件**：`src/pages/index.astro`

**参考**：技术方案 5.2 → AC-001, AC-002, AC-041, AC-042

**依赖**：Task-12（Sidebar 组件已存在）

**预估工时**：25 分钟

**验证标准**（TDD RED 阶段依据）：

- [x] 桌面端（≥1024px）呈左右两栏布局
  - **Given** 桌面浏览器宽度 ≥1024px，**When** 访问首页，**Then** Sidebar 固定约 288px 宽在左侧，文章列表在右侧占据剩余空间，两栏并排显示
- [x] 移动端（<1024px）呈上下堆叠布局
  - **Given** 移动/平板浏览器宽度 <1024px，**When** 访问首页，**Then** Sidebar 在上、文章列表在下，各占满宽，Sidebar 内容居中对齐
- [x] 文章列表仍正常展示，无布局破损
  - **Given** 存在已发布文章，**When** 访问首页，**Then** 每篇文章卡片显示标题、日期、摘要；长标题仍正确截断（AC-020 保持）
- [x] 空文章状态在两栏布局中仍正常显示
  - **Given** 无已发布文章，**When** 访问首页，**Then** 右侧显示"暂无文章"提示，左侧 Sidebar 统计均为 0
