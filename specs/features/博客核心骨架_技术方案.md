# 博客核心骨架 — 技术设计文档

## 1. 设计概要

**功能描述**：搭建博客六大页面（首页、文章详情、分类、标签、归档、关于），深色/浅色主题切换，响应式布局，自动部署。

**影响范围**：`src/pages/`、`src/components/`、`src/layouts/`、`src/utils/`、`src/content.config.ts`、`astro.config.mjs`

**技术难点**：无 — 纯静态展示型功能，无复杂交互逻辑

**外部依赖**：GitHub Actions + GitHub Pages（已配置）

---

## 2. 架构概览

本项目是 Astro 纯静态站点，数据流极为简单：

```mermaid
sequenceDiagram
    participant MD as Markdown 文件<br/>(src/content/blog/)
    participant CC as Content Collections<br/>(Zod Schema 校验)
    participant UTIL as content.ts<br/>(查询/过滤/分组)
    participant PAGE as Astro 页面<br/>(路由层)
    participant HTML as 静态 HTML<br/>(构建产物)

    MD->>CC: 构建时加载 + frontmatter 校验
    CC->>UTIL: getCollection("blog")
    UTIL->>PAGE: 过滤 draft、排序、分组
    PAGE->>HTML: Astro 渲染为纯 HTML
```

所有页面在构建时预渲染，运行时零 JS（除主题切换按钮这一个 Preact Island）。

### 3.4 日期格式化调整

**文件**：`src/utils/date.ts`

```ts
// 当前：formatDate 返回 zh-CN 格式 → "2026/05/10"
// 改为：YYYY-MM-DD 格式 → "2026-05-10"
export function formatDate(date: Date): string {
  const y = date.getFullYear();
  const m = String(date.getMonth() + 1).padStart(2, "0");
  const d = String(date.getDate()).padStart(2, "0");
  return `${y}-${m}-${d}`;
}
```

### 5.4 图片缺失占位

在文章渲染层（`BlogPostLayout.astro`）添加全局 `<img>` 错误处理——通过 `onerror` 替换为占位文字。使用内联 `<script>` 实现：

```js
document.querySelectorAll('article img').forEach(img => {
  img.addEventListener('error', () => {
    img.replaceWith(Object.assign(document.createElement('span'), {
      textContent: '图片未找到',
      className: 'text-gray-400 italic'
    }));
  });
});
```

### 5.6 首页侧边个人信息栏 (CR-004)

**文件**：`src/components/Sidebar.astro`（新建）

独立的个人信息栏组件，内部划分为四个子区域：

**a) 个人资料区**：
- 头像：`<img>` 大尺寸圆角（`h-24 w-24 rounded-full`），从 `SITE_AVATAR` 读取
- 作者昵称：`<h2>` 从 `SITE_AUTHOR` 读取
- 个人简介：`<p>` 从 `SITE_BIO` 读取

**b) 社交图标区**：
- 从 `siteConfig.socialLinks` 遍历渲染
- 每个图标为 `<a>` 内嵌 SVG，`target="_blank" rel="noopener noreferrer"`
- 图标大小 20x20，hover 变色
- 支持的 icon 名与 SVG 映射在组件内以内联对象维护（约 3-5 个常用图标，每个 SVG 约 200 字节）

**c) 统计区**：
- 通过 Props 接收 `postCount`、`categoryCount`、`tagCount`
- 显示为 3 个统计块，排列方式：横排或竖排均可
- 数字加粗，下方小字标注

**d) 导航菜单区（CR-005 修订）**：
- 链接列表：首页(`/`)、关于(`/about/`)、友链(`/friends/`)（分类/标签/归档已归入 Header 文章▼，不在此重复）
- 每项带 `icon` 字段，渲染 SVG 图标 + 文字，图标风格与 Header 一致（线条风、`h-4 w-4`）
- hover 时文字变主题色，轻微左移（`hover:translate-x-1 transition-transform`）

**Props 接口**：

```ts
export interface Props {
  postCount: number;
  categoryCount: number;
  tagCount: number;
}
```

## 8. 技术决策

### 移动端菜单：内联 JS vs Preact Island

- **A**: Preact Island — 与 ThemeToggle 同技术栈，状态管理方便
- **B**: 内联 `<script>` — 零依赖，约 10 行代码，体积极小

**结论**：选 B。汉堡菜单逻辑极简（切换 class + 关闭回调），不值得引入 Preact 组件的运行时开销。

### 关于页：Content Collection vs 直接 import

- **A**: 建立 `src/content/about/` Collection — 需定义 Schema，可扩展多篇"页面"
- **B**: 直接 `import { Content } from '../content/about.md'` — 零配置，单个文件足够

**结论**：选 B。只有一篇关于页，Collection 的 Schema 定义和查询开销没有收益。
