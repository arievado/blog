# 技术栈选型

## 1. 核心决策 (Key Decisions)
产品约束决定了技术路线的选择逻辑：

| 约束 | 推导 | 最终选择 |
|------|------|----------|
| 零成本部署、无后端 | 纯静态站点生成器（SSG） | Astro |
| Markdown + Git 工作流 | 内容即文件，构建时生成页面 | Astro Content Collections |
| 全文搜索 + 无服务器 | 构建时生成静态搜索索引 | Pagefind |
| 2–4 周上线 | 需要开发效率高、学习曲线低的框架 | Astro + TailwindCSS |
| 第三方评论 | 基于 GitHub Discussions | Giscus |
| 零成本部署 | 免费静态托管 + CI/CD | GitHub Pages + GitHub Actions |
| 响应式 + 深色模式 | 原子化 CSS，内置暗色方案 | TailwindCSS |

**核心原则**：选最适合内容的，不选最热门的。Astro 是当前内容型站点（博客、文档、营销页）的最优解，而非妥协。

## 2. 前端 (Frontend)
*   **框架**: Astro（v4+，静态站点生成器，默认零 JavaScript 输出）
*   **样式方案**: TailwindCSS（v3+，原子化 CSS，原生支持深色模式）
*   **UI 交互增强（按需）**: 必要时使用 Astro Island 引入 Preact 组件（如搜索框、深色模式切换按钮），不用 React/Vue 全家桶
*   **搜索**: Pagefind（构建时索引 HTML，零运行时依赖，支持中文）
*   **评论**: Giscus（基于 GitHub Discussions，无追踪，零成本）

## 3. 后端 (Backend)
**本项目为纯静态架构，无运行时后端。**

*   **API 协议**: 不适用——所有页面在构建时预渲染为静态 HTML
*   **评论的后端由 Giscus (GitHub Discussions API) 承担**，不经过自有服务器

## 4. 数据存储 (Database)
**本项目无数据库。** 数据存储方式如下：

*   **内容源（主数据）**: 本地 Markdown 文件（`src/content/`），Git 版本控制
*   **文章元数据**: Markdown frontmatter（YAML 格式，含 title、date、category、tags）
*   **评论数据**: GitHub Discussions（Giscus 自动管理）
*   **搜索索引**: Pagefind 构建时生成的静态 JSON 文件

## 5. 基础设施 & 工具 (Infra & Tools)
*   **部署**: GitHub Pages（通过 `gh-pages` 分支托管静态文件）
*   **CI/CD**: GitHub Actions（监听 `main` 分支 push → `astro build` → 部署到 `gh-pages`）
*   **域名**: 前期使用 `<username>.github.io` 免费二级域名，后续可绑定自定义域名
*   **包管理**: pnpm（磁盘空间友好，安装速度快）
*   **代码托管**: GitHub（公开仓库）
*   **运行时**: Node.js 18+ LTS

## 6. 版本信息
*   **锁定方式**: `package.json` + `pnpm-lock.yaml` 锁定依赖版本
*   **Node 版本**: `.nvmrc` 或 `package.json engines` 声明 Node 18+
